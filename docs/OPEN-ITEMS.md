# Open items

Shared code that several sites now copy by hand. Each one moves into site-kit with tests and a release, then squarefitimage.com switches to it first and proves it (full check, phone run); the other sites adopt it the next time they're worked on, through the weekly sweep's site-kit bump. One branch per item. Tick an item with its release tag and evidence.

Found on 2026-11-26 while reviewing squarefitimage.com against the image sites in `D:\Github-New` (bgremoverbulk.com, circlecropimages.com, mergejpgonline.com, photoresizerr_com).

Suggested order: 2 and 6 first (small, safe), then 1 (largest), then 3, 4, 5 and 7.

- [ ] 1. **Image input engine** as `site-kit/image`, one subpath per piece so a page ships only what it imports: open and decode with EXIF orientation, HEIC fallback, read the pixel size from the file header to refuse huge files before decoding, friendly "can't open" errors, ZIP writer, download helper, batch runner. Today it exists in 5 sites and has drifted: HEIC handlers of 107 (circlecropimages), 165 (bgremoverbulk) and 250 lines (photoresizerr), ZIP writers of 135 (squarefitimage `src/lib/image/zip.ts`) and 240 lines (bgremoverbulk `src/lib/zip/zip.ts`). Start from photoresizerr's copy (`lib/image/`, the most complete), merge what the others fixed, keep the fixtures as tests (HEIC, rotated JPEG, damaged file, 100 MP header). Closes when it's released and squarefitimage uses it with `bun run check` and a phone run passing.
- [ ] 2. **Analytics with consent** as `site-kit/seo/analytics`: GA4 or GTM, consent denied by default in the EEA, UK and Switzerland, the script loaded after the page `load` event, plus the Google, Bing and Yandex verification meta tags from config. Today squarefitimage (`src/lib/analytics.ts`, 30 lines) and bgremoverbulk (36 lines) differ on 66 lines, so a privacy fix in one never reaches the other. Closes when it's released, both sites' snippets come from it, and the GA collect request still fires on a production build with no CSP error.
  - Released in v1.7.0 (`seo/analytics`: consent default, load after `load`, ID check, `<` escaping, standard `gtm.js` push, `verificationMeta`). squarefitimage switched in `cc4fa8a`: its production build under `wrangler dev` sends one GA collect hit, as the live site does, with no CSP or console errors. **Still open:** bgremoverbulk does not depend on site-kit yet, and its privacy copy describes loading on first interaction with no consent default; switching it means adding site-kit and updating that copy.
- [ ] 3. **Phone test helpers** in `site-kit/playwright`: swipe and pinch through CDP `Input.dispatchTouchEvent`, Android Back, and file steps (upload a fixture, assert the saved file's type and pixel size, count ZIP entries). squarefitimage wrote its own in `verify/sheet.spec.ts` and `verify/tool-steps.ts`; the workflow's verify step now requires gesture tests on every site. Closes when squarefitimage's specs import them and pass on the `phone` project.
- [ ] 4. **Real-phone runner** as a `site-kit phone` command: `adb devices`, `adb forward tcp:9222 localabstract:chrome_devtools_remote`, Playwright `connectOverCDP`, `emulateMedia({ colorScheme: null })` so the phone's own theme shows, `Browser.setDownloadBehavior` reset so downloads work, fixtures pushed with `adb push` (never tap the photo picker), and a clear message when the phone is locked. Rebuilt by hand in several squarefitimage sessions and never saved; the launch gate now requires a real-phone run. Closes when it runs a site's Core interactions on a connected phone and prints pass or fail per row.
- [ ] 5. **Per-page social cards** as a `site-kit og` command: renders a 1200 x 630 card per indexable page from a small config (headline, sub line, image or image pair) on a brand layout the site supplies, writes `public/og/<slug>.png`, and a check that every indexable page has one. squarefitimage's `scripts/og-cards.mjs` (99 lines) hard-codes its 15 cards; the launch gate requires per-page cards on every site. Closes when squarefitimage's cards come from it unchanged pixel for pixel or better.
- [ ] 6. **Trailing-slash redirects** as a `site-kit redirects` command: writes `public/_redirects` from `SITE_PAGES` (each page without its slash, and `/index.html`, 301 to the canonical path), so Cloudflare's `auto-trailing-slash` never answers with a 307. squarefitimage's `scripts/redirects.ts` (12 lines) is the source. Closes when squarefitimage's build uses it and the live 301s still pass `postdeploy-check.mjs`.
  - Released in v1.7.0 (`site-kit redirects`, built from the pages in `dist`). squarefitimage switched in `cc4fa8a`: the same 22 rules, and `/about`, `/square-crop` and `/index.html` 301 under `wrangler dev`. **Still open:** the live 301 check after squarefitimage's next deploy.
- [x] 7. **Changelog grouping** (newest first, by month and year) next to the changelog types. squarefitimage's `src/lib/changelog/group.ts` (30 lines) is the source. Small; closes when squarefitimage's `/changelog/` renders from it.
  - Done in v1.7.0 (`seo/changelog`, generic over any entry with an ISO date). squarefitimage's `/changelog/` renders from it since `cc4fa8a`, with `bun run check` passing (144 unit, 54 browser tests).

Not for site-kit (UI that sites restyle, so it goes in the claude-workflow templates instead): squarefitimage's accessible FAQ, `src/components/FaqList.astro` (heading-wrapped button, `hidden="until-found"`, works without JavaScript), which should replace the templates' `<details>` FAQ.
